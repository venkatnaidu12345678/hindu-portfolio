NearDeals: Engineering a Location-Based Commerce Platform

A case study by Ravuri Harsha, React Native & Full-Stack Engineer, on building the mobile app and backend behind NearDeals — a discovery platform connecting buyers with nearby single and chain dealers.

▶ Play Store ← Back to portfolio section ✉ Ask about it

Overview

NearDeals is a local commerce discovery platform — an Android app backed by a Node.js/Express API — that connects nearby buyers with real shops and dealers. It covers both single dealers (independent shops) and chain dealers (multi-branch retailers), each with their own product catalog and store profile.

Problem

Local buyers often can't tell which nearby store actually stocks a product, at what price, or how far away it is — search is fragmented across calls, walk-ins, and outdated listings. Store owners, meanwhile, have no lightweight way to publish their catalog and be discovered by distance.

Solution

A catalog and discovery layer built around location: users search or browse by category, see results ranked by distance and store reliability, and open a product/store detail view with specs, pricing, offers, and direct contact (call, WhatsApp, directions).

My Contribution

Engineering the Android application UI and the backend API layer — including the product/catalog domain (models, services, controllers, validation), dealer and store management, category structure, and the location/distance-based discovery logic.

Architecture & Engineering Decisions

Dealer modelDistinct data model for single dealers vs. chain dealers, so a chain's branches share a catalog while remaining independently discoverable stores.
Catalog service layerProduct domain split into model / service / controller / validation layers with normalized naming and indexed lookups for fast search.
Location-based discoveryStore and product results ranked by proximity, so "what's near me" resolves quickly against a growing store network.
AuthenticationToken-based auth separating buyer and dealer roles, gating store/catalog management behind verified dealer accounts.

Technology Used

React NativeNode.jsExpressMongoDB (Mongoose)REST APIs

Key Engineering Challenges

  • Modeling a catalog that works identically for a single independent shop and a multi-branch chain, without duplicating product data per branch.
  • Keeping search and distance-ranking responsive as the store and product count grows — this required indexed queries over ad-hoc collection scans.
  • Designing category and product schemas flexible enough for very different store types (electronics, mobiles, appliances) without becoming unmanageably generic.

Performance & Scalability

Search, filtering, and product-detail screens are built to stay responsive as catalog size grows — indexed MongoDB queries on the fields users actually filter by, and a mobile UI designed to load progressively rather than block on a full catalog fetch.

Security Considerations

Store and catalog management endpoints are gated behind authenticated dealer accounts, separating public read access (browsing, search) from write access (product/catalog edits), so only verified dealers can modify their own store's listings.

Result

NearDeals is live on the Play Store, with a production Android client and backend supporting an active, growing network of single and chain dealers across categories.
